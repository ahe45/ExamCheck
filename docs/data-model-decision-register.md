# 목표 데이터 모델 외부 결정 기록부

> 상태: 승인 대기  
> 제안 근거: `docs/adr/0002-target-identity-model-proposal.md`  
> 실행 게이트: `docs/data-model-cutover-gates.md`

이 문서는 목표 identity 모델과 운영 전환에 필요한 D-01~D-22 결정을 한 곳에서 승인하기 위한
기록 양식이다. 선택하지 않은 항목을 기본값으로 간주하지 않으며, 결정 전에는 목표 identity
migration `027` 이상, 운영 backfill, read/write cutover를 실행하지 않는다. 현재 스키마 latest는
현 모델의 감사 request ID 폭만 보강한 `026_expand_audit_request_id.sql`이다.

## 승인 규칙

- 각 행에는 선택 결과, 예외, 책임자, 승인자, 승인 일시와 적용 시험 주기를 기록한다.
- 유일 정책과 정규화처럼 기존 데이터에 영향을 주는 결정에는 충돌 집계와 rollback 조건을 첨부한다.
- 결정 변경은 기존 행을 덮지 않고 revision을 올려 변경 이유와 영향 범위를 남긴다.
- 개인정보 원문이나 실제 수험번호·가번호 예시는 기록하지 않는다.

## 현 운영 모델에서 이미 확정된 범위

아래 결정은 현재 `candidate_record` 기반 운영 모델에서 사용자가 명시적으로 확정했고 구현·검증됐다.
목표 identity 모델의 `027+` migration 승인과는 구분한다. 현재 026은 감사 request ID 길이만
확장한 현 모델 보강이며 목표 identity 결정의 선행 승인을 뜻하지 않는다.

- 수험번호·가번호 유일 범위는 고정값이 아니라 개발자 메뉴에서 변경한다.
- 수험번호는 `SYSTEM` 또는 `SCHEDULE`, 가번호는 `ADMISSION` 또는 `SCHEDULE`을 선택한다.
- 정책을 강화할 때 기존 데이터가 충돌하면 원문을 노출하지 않고 저장 전체를 취소한다.
- 전형이 배정되지 않은 사용자 계정은 현재 모델에서 모든 전형·교시에 접근한다.

유일 정책의 현재 의미와 DB 제약은 [ADR 0001](./adr/0001-pseudonym-unique-scope.md)에 확정돼 있다.
다만 `SYSTEM`을 향후 시험 주기 전체와 동일시할지, 무배정 계정을 명시적 `ALL` 값으로 어떻게
이관할지는 목표 모델 결정으로 남는다.

## 결정별 필수 증거

각 결정에는 필요한 경우 다음 비식별 증거를 연결한다.

- source/target/exact/unmapped/ambiguous 건수
- NFKC·trim 충돌 그룹 수
- 유일 정책별 충돌 그룹과 영향을 받는 내부 ID 수
- 범위 capacity sum, union capacity, 대상 수와 deficit
- `ALL/ASSIGNED` 계정 수와 비정상 조합 수
- old/new salted shadow match/mismatch 집계
- 실제 MariaDB 통합·부하·lock 검증 결과
- UI/API contract, 역할별 권한, FHD/QHD/소형 해상도 검증 결과

비파괴 테스트는 계속 개선할 수 있지만 운영 데이터나 schema는 변경하지 않는다.
