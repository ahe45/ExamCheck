# ADR 0001: 수험번호·가번호 유일 범위를 개발자 설정으로 관리

- 상태: 승인됨
- 결정일: 2026-08-28
- 적용 버전: DB migration 019~021

## 배경

수험생 업로드 행은 날짜·시작 시간·교시별로 존재하지만, 기존 수험생과 가번호 할당은 수험번호 한 건을 기준으로 연결되어 있었다. 이 구조에서는 같은 수험번호가 여러 교시에 등록되거나, 서로 다른 교시에서 같은 가번호 범위를 사용할 때 실제 운영 정책과 DB 제약이 어긋날 수 있다.

학교별 운영 방식이 다를 수 있으므로 하나의 범위를 코드에 고정하지 않고 개발자 권한이 런타임 정책으로 선택하도록 한다. 정책 화면만 바꾸는 것은 허용하지 않으며, 업로드·사전부여·직접부여·추첨·순차부여·마감 자동부여·조회·출력과 DB 고유 제약이 동일한 범위를 사용해야 한다.

## 결정

### 수험번호

| 설정값     | 화면 명칭   | 의미                                                                                                                  |
| ---------- | ----------- | --------------------------------------------------------------------------------------------------------------------- |
| `SYSTEM`   | 시스템 전체 | 모든 전형·날짜·교시를 통틀어 동일 수험번호의 등록 행을 한 건만 허용한다.                                              |
| `SCHEDULE` | 교시별      | 동일한 날짜·시작 시간·교시 안에서만 수험번호가 유일하다. 다른 날짜·시간·교시에는 같은 수험번호를 다시 등록할 수 있다. |

`examinee`는 현재도 수험번호 기준의 공통 인적 식별 행으로 유지하고, 실제 응시 일정과 가번호 할당의 정체성은 `candidate_record`가 담당한다. 따라서 `SCHEDULE`은 동일 인적 식별자가 여러 응시 일정에 참여하는 것을 허용하는 정책이다.

### 가번호

| 설정값      | 화면 명칭 | 의미                                                                                                                 |
| ----------- | --------- | -------------------------------------------------------------------------------------------------------------------- |
| `ADMISSION` | 전형 전체 | 같은 시험·전형의 모든 날짜·교시를 통틀어 가번호가 유일하다.                                                          |
| `SCHEDULE`  | 교시별    | 같은 시험·전형·날짜·시작 시간·교시 안에서 가번호가 유일하다. 서로 다른 교시에서는 같은 가번호를 다시 사용할 수 있다. |

교시별 scope key는 `시험일자 + 시작 시간 + 교시명 + 전형명`의 정규화 문자열을 SHA-256으로 계산한다. 모집단위·전공·건물·고사실은 가번호 범위를 나누는 세부 행이지만, 동일 교시의 운영 명단 안에서 가번호가 충돌하지 않도록 유일 범위에는 포함하지 않는다.

### 변경 권한과 충돌 처리

- 정책 조회·변경 UI는 개발자 권한에만 제공한다.
- 정책 저장과 업무 쓰기는 `system_profile` 행 잠금을 공유해 서로 직렬화한다.
- 더 넓은 재사용을 허용하는 방향의 변경은 기존 할당 scope key를 다시 계산한 뒤 적용한다.
- 더 강한 유일 정책으로 변경할 때 기존 충돌 그룹이 하나라도 있으면 전체 저장을 취소하고 충돌 그룹 수만 반환한다. 수험번호·이름·가번호 원문은 오류 메시지나 로그에 포함하지 않는다.
- 새 가번호 쓰기는 `candidate_record_id`당 한 건, 그리고 정책 scope key 안에서 번호당 한 건이라는 DB unique 제약으로 최종 보호한다.

## 레거시 데이터

기존 할당은 수험번호와 전형으로 정확히 한 개의 `candidate_record`가 확인되는 경우에만 일정 행에 연결한다. 후보가 없거나 둘 이상이면 자동 추정하지 않고 `candidate_record_id = NULL`인 레거시 행으로 보존한다. 이 행은 삭제하지 않으며 빈 scope key를 사용해 기존처럼 전형 전체 예약 번호로 취급한다.

현재 로컬 DB 기준 전체 할당 11건 중 6건은 정확히 연결됐고 5건은 레거시 미매핑 상태로 보존됐다.

## 결과와 후속 작업

이 결정으로 복수 교시 수험번호와 교시별 가번호 재사용의 운영 경로는 지원한다. 다만 다음 항목은 별도 데이터 모델 전환에서 계속 처리한다.

- 이름 기반 전형·일정 관계를 안정적인 ID 관계로 교체
- `candidate_record`와 `examinee`의 이중 원본 정리
- 가번호 숫자 canonical 값과 `001` 같은 표시 자릿수 분리
- 레거시 미매핑 5건의 보존·이관·삭제 결정
- 신규 모델 dual-write, shadow read, reconciliation 후 cutover

따라서 이 ADR은 RF-033과 P0-4의 운영 가능한 수직 슬라이스를 승인하지만 Phase 5 전체 완료를 의미하지 않는다.
